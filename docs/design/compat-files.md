# Manifest-owned compatibility files

M63a introduces compatibility files as explicit manifest-owned generated files.
Compatibility files are ecosystem support files such as editor settings or tool
configuration. TSPack may generate them, but the manifest must declare ownership.

## File categories

- Observed files are read only. M62a package.json observation is the current
  example.
- Managed compatibility files are generated by TSPack with full-file ownership.
  M63a supports JSON files only.
- Projected ecosystem files, including package.json projection, are future work.

## M63a scope

M63a supports `<CompatFiles>` with `<JsonFile path="..." value={...} />` in
`manifest.tsx`. JSON values may be objects, arrays, strings, numbers, booleans,
or null. Rendering is deterministic: stable object key ordering, two-space
indentation, and a trailing newline.

The explicit commands are:

- `tspack compat list`
- `tspack compat diff`
- `tspack compat write`

`check`, `sync`, and `init` do not write compatibility files.

## Non-goals

M63a does not manage package.json, lockfiles, YAML, TOML, JavaScript config,
TypeScript config source, arbitrary text patches, merge mode, partial ownership,
JSON pointer ownership, or automatic writes.

## Future work

Future milestones may add typed helpers for common config files, structured merge
or JSON path ownership, package.json projection previews, concept-authored config
projections, and `init --alongside` consuming compat declarations.
