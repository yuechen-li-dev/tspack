## Interpretation

On this Windows machine, deterministic parallel resolve materially improved cold update throughput versus forced serial. The current default fixed resolver mode at `jobs=24` averaged `7.80 s` for cold update versus `24.70 s` for the forced serial baseline, roughly a `3.2x` speedup for total cold update wall time in this benchmark pass.

The store-population work added in M66a remains effective here. Cold update still fetched metadata and tarballs, but artifact capture during resolve left `0` packages needing follow-up store population and only about `16-17 ms` in the `update.store_population` phase. In other words, the post-resolve store step was nearly eliminated in this pass.

Hardlink-first materialization is also showing up cleanly. First sync materialized `10716` files with `10716` hardlinks and `0` copy fallbacks. On this machine and fixture, the materialization path stayed fully on the hardlink-first fast path.

Warm sync is now near no-op when the projection is current. Across the fixed `jobs=24` runs, warm sync averaged `0.23 s`, hit the materialization marker, skipped `329` packages and `10716` files, and performed no fresh hardlink or copy work. That is the clearest current-main confirmation of the M66c marker fast path.

Feedforward remains available but is not default because the current-main evidence is mixed rather than decisive. In this benchmark pass, feedforward at `jobs=24` averaged `7.84 s` for cold update versus `7.80 s` for fixed at `jobs=24`, while targeting fewer average jobs (`11.67` versus `15.0`) under the same host budget. That is close enough to treat as a tie in practice here, not a reason to change the stabilized default from `fixed`.

Future work still belongs in measurement and controller tuning rather than semantic changes. The benchmark evidence suggests the next questions are around occupancy tuning, host-budget strategy, and broader workload coverage, not resolver semantics, lockfile format, or changing defaults from one local pass.

## Release-note-ready summary

- Added deterministic parallel resolver preparation for faster cold updates while preserving byte-identical lockfile output; in this Windows benchmark pass, forced serial cold update was `24.70 s` and fixed parallel `jobs=24` averaged `7.80 s`.
- Avoided duplicate post-resolve store work by capturing artifacts into the store during resolution; this pass captured `121` artifacts and left `0` packages needing store population, with only about `16-17 ms` spent in the store-population phase.
- Added hardlink-first `node_modules` materialization to reduce duplicate copy work; first sync materialized `10716` files with `10716` hardlinks and `0` copy fallbacks on this machine.
- Added no-op sync detection so repeated syncs skip full `node_modules` rematerialization when the plan is unchanged; warm sync averaged `0.23 s` and skipped `329` packages plus `10716` files in this pass.
- Added a performance and pprof harness for update and sync profiling, with isolated benchmark projects, isolated stores, per-scenario perf JSON, and optional profiles under `dist/bench/...`.
- Added an experimental feedforward resolver occupancy controller behind configuration; it remains available for benchmarking, but the v0.1.7 default stays `fixed` because this local pass did not show a clear win over the stabilized default.
